# waitlist

进程内选课候补组件（Go 库）。退课释放的座位与学分会激活候补，
任何可见状态都不超卖座位、不超过学生 21 学分上限。

## 语义

- `New(students, sections)`：初始化学生集合与各教学班（固定容量、1–6 整数学分）。初始无人选课。
- `Enqueue(ticket, student, section)`：提交选课请求。`ticket` 为调用方提供的唯一正整数，越小递补优先级越高。先入候补，返回前完成本轮递补。
- `Cancel(ticket)`：撤销候补或已选请求；撤销已选请求同时释放座位与学分，返回前完成递补。重复撤销无副作用。
- `Inspect(students, sections)`：返回指定学生与教学班的一致快照（已选关系、已选学分、候补顺序）。

递补规则：每步从所有当前可递补请求中取 ticket 最小者转为已选，直到没有可递补请求。
可递补 = 教学班有空位 且 加入后学生学分 ≤ 21。学分不足的较早请求不阻塞较晚但符合条件的请求；
已选上的请求不会被更小 ticket 挤出。所有操作（含 Inspect）均可线性化。

## 用法

```go
s := waitlist.New(
    []string{"alice", "bob"},
    map[string]waitlist.SectionSpec{
        "CS101-1": {Capacity: 1, Credits: 3},
        "CS102-1": {Capacity: 2, Credits: 6},
    },
)
s.Enqueue(1, "alice", "CS101-1") // 有空位，直接选上
s.Enqueue(2, "bob", "CS101-1")   // 满员，进入候补
s.Cancel(1)                      // alice 退课，bob 自动递补
snap := s.Inspect([]string{"bob"}, []string{"CS101-1"})
// snap.Students["bob"].Credits == 3
// snap.Sections["CS101-1"].Enrolled == 1
```

未知学生/教学班、非正数或重复 ticket、学分越界的课程配置会 panic（视为编程错误）。

## 并发设计

- 学生与教学班构成二分图，请求（候补或已选）为边；每个连通分量一把锁，
  操作只锁住本次关系变化牵连的分量，互不相连的分量完全并行。
- 全局仅有一把保护登记信息（ticket 表、并查集）的短锁，选课/撤销/递补/读取
  均不在其保护下执行。
- 分量只合并不分裂：Enqueue 连接两个分量时在持锁状态下原子合并；
  加锁后重新校验归属，失效则重试。所有多分量加锁按分量 id 排序，无死锁。
- 递补是不动点闭环：每次操作结束时系统不存在可递补请求，因此一次退课只需在
  被释放座位所在班与退课学生候补所在班的闭包内按 ticket 最小优先递补，
  无需遍历全校，也无后台补偿。

## 测试

```sh
go test -race ./...
```

覆盖：顺序语义（递补顺序、学分上限、跨班学分激活、不挤出）、
并发学分上限与并发读取的可线性化、退课后的优先级递补与撤销交错、
不相连分量在临界区暂停下的独立性（可控暂停，无 sleep 碰运气）、
以及基于顺序参考模型的短并发历史线性化检查（Wing-Gong 回溯）。
